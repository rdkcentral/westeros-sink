## What Each Phase Does

### Phase 1: Media Metrics ✅ COMPLETE

**Implementation**: Notify playback metrics (frame drops, decode errors, etc.)

**API**:
```cpp
void notifyMetric(const MetricEvent &metric);
bool getFrameCounters(FrameCounters &counters);
bool setMetricSubscription(const std::set<MetricType> &types);
```

**GStreamer Message**:
```
media-pipeline-metric {
    metric: enum (1-7),
    observation-kind: enum (1-3),
    source_id: uint,
    pts-ns?: int64,
    duration-ns?: uint64,
    count?: uint64
}
```

**Status**: ✅ Pushed to rialto + rialto-gstreamer

---

### Phase 2: Metric Optimization (2.5 days)

**Problem**: One global subscription list, no per-client filtering

**Solution**:
- Track subscriptions per client
- Batch events to reduce RPC overhead
- Optimize for 1000+/sec metric scenarios

**Changes**:
- `m_subscribedMetricTypes` → `m_clientSubscriptions` map
- Add metric queue + batch timer
- Conditional posting based on client subscription

**Use Case**: High-frequency metric consumption

---

### Phase 3: Video Frame Capture (7-10 days) ⚠️

**Problem**: Apps can't efficiently access captured video frames

**Solution**: Direct GPU texture/image capture

**API**:
```cpp
class IVideoFrameCapture {
    bool getCapabilities(VideoFrameCaptureCaps &caps);
    bool registerCapturePool(GraphicsAPIType api, const std::string &poolId);
    bool getFrameCapture(VideoFrame &frame);
    bool returnFrame(const VideoFrame &frame);
};
```

**Data Types**:
- GraphicsAPIType (OpenGL, Vulkan)
- VideoFrameCaptureCaps
- VideoFrame (with GL/Vulkan handles, DMA-BUF)
- GraphicsTextureLayout (RGBA, NV12, I420)

**Use Case**: Netflix VaaT V2, texture-based rendering, PGIO

**⚠️ Complexity**: Highest - requires GPU expertise, DMA-BUF management

---

### Phase 4: Audio Discontinuity (3-5 days)

**Problem**: No structured way to track audio gaps/transitions

**Solution**: Metadata-driven discontinuity markers

**Structure**:
```cpp
struct AudioDiscontinuity {
    AudioDiscontinuityType type;  // CONTENT_TRANSITION, PRESENTATION_GAP, etc.
    int64_t discontinuityDurationMs;
};
```

**Integration**: Attached to audio segments

**Deprecation**: `processAudioGap()` → metadata-based

**Use Case**: Program transitions, ad breaks, content alignment

---

### Phase 5: KeyStatus Parity (1-2 days) ⚡

**Problem**: KeyStatus enums missing, OCDM conversion incomplete

**Solution**: Add missing enum values, fix conversion functions

**Changes**:
```cpp
enum KeyStatus {
    // ... existing values ...
    OUTPUT_DOWNSCALED,    // NEW (HDCP downscaling)
    USABLE_IN_FUTURE      // NEW (Key timing)
};
```

**Effort**: Minimal - just enum additions + OCDM wrapper fixes

**Impact**: W3C EME specification compliance

**⏱️ FASTEST PHASE**: 1-2 days!

---

### Phase 6: Device Individualization (2-3 days) OPTIONAL

**Problem**: No device provisioning callback

**Solution**: Optional individualization request callback

**API**:
```cpp
void onIndividualizationRequest(const std::string &challengeData);
```

**Use Case**: Device-specific DRM provisioning

**Note**: Optional - not required for V1.1 conformance

---

### Phase 7: Persistent Licenses (4-6 days)

**Problem**: Process crash loses license context

**Solution**: Save/restore persistent session IDs

**API**:
```cpp
bool loadSession(int32_t mediaKeySessionId, 
                 const std::string &persistentSessionId);
void onLicenseRelease(const LicenseReleaseEvent &event);
```

**Flow**:
1. Save persistent session ID
2. On recovery, call loadSession() with saved ID
3. License restored, playback resumes

**Use Case**: Process crash recovery, multi-instance playback

---

### Phase 8: Application Lifecycle Reclaim (5-7 days)

**Problem**: No generic resource reclamation framework

**Solution**: Generic notifyReclaimed() callback

**API**:
```cpp
void notifyReclaimed(ResourceType type, ReclaimReason reason);

enum ResourceType {
    MEDIA_PIPELINE,
    WEB_AUDIO_PLAYER,
    MEDIA_KEYS_SESSION,
    GPU_MEMORY,
    SYSTEM_MEMORY,
    OTHER
};

enum ReclaimReason {
    RECOVERED_RESOURCE,
    MEMORY_PRESSURE,
    LOW_BATTERY,
    SHUTDOWN,
    APP_BACKGROUNDING,
    OTHER
};
```

**Use Case**: Resource cleanup on memory pressure, battery optimization, app backgrounding
